# Task 2 interpretation

- T2.md was absent. The user request is preserved as its source, without inventing additional task requirements.
- "Before any parsing" means before the image/PDF content decoder, OCR, text extraction, or LLM. The gate must itself inspect bounded framing/header structures, dimensions, PDF names, and compressed streams to validate safety. This cannot literally occur without reading the format structure. Tests prove unsafe payloads never reach a content parser.
- The supported allowlist is PNG, JPEG, and a conservative PDF subset. Archives, animations, encrypted PDFs, object/xref streams, incremental PDFs, attachments/actions/forms/scripts, and unsupported compression/filter arrangements are rejected. Legitimate but unsupported PDFs should be exported to a simple PDF or static image. This is a fail-closed upload gate, not a claim of universal malware detection or a replacement for OS process isolation.
- Original labelled field values are preserved. Only explicitly labelled values are extracted; missing values and regions remain null. Conflicting values inside a document require clarification. Confidence is OCR word confidence, or 1 for exact native text mapping; it is not proof that an invoice is genuine.
- Date and amount normalization is used only for comparison, using configured formats/currency aliases. Customer-message values never fill a missing document field. Quality rejection takes precedence over treating uncertain OCR as a factual mismatch.
- Product purpose is chosen explicitly by the caller. OCR/security checks precede vision. The already configured Gemini 2.5 Flash provider is reused for image input. An absent/unsupported model or missing credential returns cannot analyse honestly. The offline demo explicitly disables vision, and pytest clears provider credentials to prevent accidental live calls.
- Sharp product photos without substantive OCR text can still reach vision; all absent OCR fields remain null. Product photos with substantive but low-confidence OCR, and blurred images, request another file. Conflicts remain visible and require clarification even when vision is unavailable.
- Jobs are durably queued before dispatch. Fast jobs return their result inline. Once Clock reports 30 seconds elapsed, the request returns HTTP 202 with job id and a processing notification while the same work continues in the background. queued/running/done/failed are persisted. Completion notifications/results are delivered through the owner-bound job polling endpoint; no external email or push provider is implied.
- Retention starts at acceptance. Purge removes the original bytes and stored customer/result content, including pending jobs. Expired in-flight work cannot publish a result. Minimal owner/id/status/expiry tombstones remain for honest expired status. One application worker owns the database; pending work is requeued on restart.
- Tesseract is an external executable, checked with --version and --list-langs. Its installed English pack and project-local official eng/hin/tel/spa packs are verified separately. Library/CLI timeouts bound native operations; application deadlines and retention use Clock.
- PyMuPDF could not load because Windows application control blocked its native module. It was removed and replaced by the successfully verified PDFium library; Windows security policy was not weakened.
