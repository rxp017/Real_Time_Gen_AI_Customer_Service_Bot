# Task 1: Controlled Knowledge Updates

Source: user-provided implementation prompt on 2026-10-13; no T1.md existed at audit time.

Read RULES.md. Reuse core/* and the RAG store from P1; do not duplicate.

Implement Task 1 exactly as follows.

- Ingestion: normalise then sha256 each file. Unchanged -> skip. Same content under a different name -> duplicate, logged and skipped. Changed -> new version.
- Validation -> quarantine/ with a reason code (empty, corrupt, unsupported type, missing metadata, oversize, injection-flagged). Never silently dropped.
- Versioning: immutable snapshots; one ACTIVE pointer; rollback(version) swaps the pointer atomically.
- Quality gate on a candidate snapshot: run a golden Q&A set (data/golden/) and measure accuracy and grounding (cited-source validity). Reject if either is lower than the active version (tolerance configurable, default 0). Report real numbers.
- Scheduler: configurable run time, driven by Clock. On failure retry at +15, +30, +60 minutes, then mark FAILED and alert. Exactly these three retries.
- Activation: approved updates are held until the configured maintenance window; activate only inside it. After activation run health checks; if they fail within 5 minutes, auto-rollback and record why.
- Access control: roles for ingest / approve / activate / rollback / view. Unauthorised calls rejected and audited.
- Prompt-injection protection on ingested docs; sensitive-data masking in logs; metrics: latency, failures, confidence, escalations.
