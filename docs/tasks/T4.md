# Task 4: Policy & Knowledge Retrieval with Controlled Generation

## Requirements & Design
1. Document metadata: version, product, region, access_level, effective_date, expiry_date, doc_family (for conflict grouping).
2. Retrieval order is fixed:
   (1) authorise by caller role,
   (2) validity filter by as_of date (default clock.now(); if the question names a past date, parse it and use it; ignore future-dated and expired for current questions),
   (3) semantic search over only the survivors,
   (4) conflict resolution: within a doc_family+product+region keep the latest applicable version,
   (5) similarity threshold.
3. Filtering happens BEFORE search, not after. Restricted text must never reach the LLM prompt.
4. Answer generation: factual claims only from retrieved chunks; each answer cites source (doc id, version, section).
5. Post-generation verifier checks every claim sentence is supported by a cited chunk; unsupported claims are removed or the answer becomes a refusal.
6. No evidence or ambiguous evidence -> refuse or ask a clarifying question (never guess).
7. Documents are untrusted: run the injection detector on chunks at ingest and at retrieval; flagged instructions are neutralised and never obeyed.

## Required Evaluation Scenarios & Named Tests
Every requirement that names an evaluation scenario needs its own named test:
- test_conflicting_policies_latest_wins
- test_restricted_doc_not_retrieved
- test_expired_policy_ignored_for_current
- test_future_dated_ignored_for_current
- test_historical_question_uses_policy_active_on_date
- test_citation_present_on_every_factual_answer
- test_refuses_when_no_evidence
- test_ambiguous_asks_clarification
- test_unsupported_claim_detected
- test_prompt_injected_doc_ignored

## Deliverables
- Fixture corpus in data/sample_docs/ covering every case above.
- Requirements Trace Matrix (docs/RTM.md) for T4.
- pytest output pasted.
- Demo script that prints real outputs.
